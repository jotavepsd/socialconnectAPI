## Desafio

Escrever o script `V2__create_doadores_table.sql` e a Entity `Doador.java` correspondente, com:

- Chave primária `id_doador`
- Colunas `nome`, `tipo` (`PESSOA_FISICA` ou `PESSOA_JURIDICA`), `email`, `telefone`
- Entity com `@Column(name = "...")` para as colunas

## Entregas

| Arquivo | Descrição |
|---------|-----------|
| `src/main/resources/db/migration/V2__create_doadores_table.sql` | Criação da tabela `doadores` |
| `src/main/java/br/com/socialconnect/api/doadores/model/Doador.java` | Entity mapeada para `doadores` |
| `src/main/java/br/com/socialconnect/api/doadores/model/TipoDoador.java` | Enum com `PESSOA_FISICA` / `PESSOA_JURIDICA` |
| `src/main/java/br/com/socialconnect/api/doadores/repository/DoadorRepository.java` | Repository JPA (usado a partir da Aula 05) |

### Decisões

- `tipo` é gravado como texto (`@Enumerated(EnumType.STRING)`) em vez do ordinal. Se a ordem do enum mudar, os dados antigos continuam corretos.
- Adicionei um `CHECK` no banco (`ck_doadores_tipo`). Assim o valor fica restrito mesmo se alguém inserir direto via SQL.
- `id_doador` usa `BIGINT GENERATED BY DEFAULT AS IDENTITY`, que funciona no H2 e no PostgreSQL, igual ao V1.

## Checklist da Revisão Cruzada

- [x] O arquivo está na pasta `db/migration`?
  Sim: `src/main/resources/db/migration/V2__create_doadores_table.sql`.
- [x] O nome do arquivo segue o padrão `V<numero>__<descricao>.sql`?
  Sim: `V2` + dois underlines + `create_doadores_table`.
- [x] A chave primária tem o prefixo `id_`?
  Sim: `id_doador`. No Java o atributo é `idDoador` (camelCase).
- [x] A Entity usa `@Column(name = "...")` corretamente?
  Sim: todas as colunas estão mapeadas explicitamente, inclusive `@Column(name = "id_doador")`.
- [x] Os tipos de dados são compatíveis (SQL ↔ Java)?
  Sim: `BIGINT` ↔ `Long`, `VARCHAR` ↔ `String`, `VARCHAR(20)` ↔ `TipoDoador` (STRING).

## Validação

Com `spring.jpa.hibernate.ddl-auto=validate`, a aplicação sobe e o log mostra:

```
Successfully applied 2 migrations to schema "PUBLIC", now at version v2
```

Se a Entity não batesse com o SQL, o Hibernate falharia na inicialização com `Schema-validation: missing column [...]`.
